# Что поменять в скриптах (версия приложения «промпты и секреты закрыты»)

Приложение больше не шлёт текст запроса к ИИ и не хранит секреты. Две вещи надо сделать на стороне Google/EmailJS,
иначе новая версия не заработает или останутся старые дыры. Я не видел ваших AiProxy.gs и Code.gs (их нет в архиве),
поэтому ниже — точные правки, а не готовые файлы.

## 1. ИИ-скрипт (AiProxy.gs)

1. Добавьте в проект Apps Script файл **AiPrompts.gs** (лежит рядом).
2. В `doPost`, после проверки токена, профиля и лимита, замените строку, где берётся `body.prompt`, на:

   ```js
   var prompt;
   try { prompt = buildPrompt_(body); }
   catch (err) { return json_({ ok: false, error: String(err.message || err) }); }
   ```
   (`json_` — ваша функция, которой скрипт отвечает приложению.) Дальше `prompt` уходит в ИИ, как раньше.
3. Старое приложение шлёт `body.prompt` без `task`. Пока не обновились все телефоны, можно временно пропускать
   такие запросы; когда обновятся — **отклоняйте любой запрос, где есть `prompt`** (иначе дыра остаётся).
   Чтобы старые телефоны обновились принудительно, поднимите `config/app.minBuild` (и включите `enforce`) —
   VersionGate уже это умеет.
4. Перепроверьте задачу `ping` («Проверить активный ключ» у администратора) и по одному запросу каждого вида:
   приём накладной, разбор названий, фото списка, штрих-код.

Задачи: recognize, identify, label, profile_gen, profile_refine, parse_one, parse_many, columns, catalog, list_photo,
barcode, ping. У каждой в AiPrompts.gs заданы лимиты на длину параметров.

## 2. Скрипт Диска (Code.gs): общий токен убран

Приложение теперь для всех (и для администратора) шлёт в параметре `token` **токен входа Firebase**, как раньше
работники. Общего секрета на телефонах, в файле настроек и в Firestore больше нет.

- Скрипт должен принимать токен входа и от администратора. Действия, которые раньше открывал общий токен
  (загрузка/удаление/обслуживание), разрешайте только если в профиле `role == admin` (или ваш признак админа).
- После проверки, что у администратора всё работает, **удалите свойство TOKEN** в Script properties и
  перевыпустите веб-приложение (новая версия).

## 3. Ротация (обязательно)

Старые файлы настроек и документ `settings/admin` в Firestore содержали секреты. Считайте их скомпрометированными:

- **Токен Диска**: сразу сменить значение (или удалить, см. п. 2).
- **EmailJS Private key**: Account → General → сгенерировать новый. В приложении он больше не нужен: в
  Account → Security «Use Private Key» должна быть **выключена**, «Allow EmailJS API for non-browser applications» — включена.
  (У работников он и раньше был пустой, так что на их входе ничего не меняется.)
- Старые файлы настроек удалить из почты, мессенджеров и облаков.

Приложение само сотрёт старые секреты с телефона при запуске, а администратору — поле `driveToken` в Firestore.

## 4. Права на удаление и контроль каталога (версия 2.38.0)

- **Code.gs**: удалять файлы и запускать «Порядок данных» может только администратор. Работнику оставлено удаление
  служебных файлов, которые приложение само перезаписывает (список `WORKER_DELETABLE_`); всё уходит в корзину Диска.
- **firestore.rules** (опубликуйте в консоли Firebase): работник больше не может пометить товар, приёмку или
  выгрузку «удалёнными» (раньше это обходило запрет на удаление). У товара при создании записывается автор, время,
  источник и номер партии; менять их потом нельзя.
- **Переходный период**: пока у кого-то старое приложение, оно не пишет автора, и правила его пропускают.
  Когда все обновились, в документе `config/app` поставьте поле `requireOrigin: true`, и товар без автора
  создать будет нельзя.
- **Приложение**: Настройки → «Контроль каталога» (только администратор): кто и сколько завёл за сутки, 7 или
  30 дней, фильтр по человеку, удаление партии целиком или по одному товару. Товары, которые уже есть в приёмках, не удаляются.

## Общие позиции обычной партии (items)

Действия `count` / `counts` расширены необязательным полем `items` (`[{sid,name,article,barcode,by,t}]`). Позиции лежат в `BATCHCOUNT_<код>.json`
(`devs[dev].items`), в ответе `counts` отдаётся объединённый список (`items`, у склеенных позиций есть `al` — прочие sid).
Для пустой партии (`"empty": true` в `BATCH_<код>.json`) `items` не сохраняются и не отдаются. После обновления Code.gs
разверните скрипт заново как **новую версию** веб-приложения.

## Журнал инвентаризации (отчёт для администратора)

- `log` (POST, публично по коду партии; из приложения — с токеном входа, код `APPINV`) — личный снимок устройства по каждой паллете
  (`INVLOG_<код>.json`: работник, товар, артикул, штрих-код, количество, время). Назад никому не отдаётся.
- `invlog` (GET) и `invlogclear` (POST) — только администратор (роль `admin` в Firestore или общий TOKEN).
- Приложение: «Прочее → Отчёт инвентаризации» (только админ): просмотр, печать, Excel (немецкий) и «Поделиться».
